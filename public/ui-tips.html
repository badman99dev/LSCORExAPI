Frontend Integration Playbook

Build a Hotstar-grade live cricket UI

Copy-paste patterns for turning raw CREX feed JSON into a broadcast-quality scoreboard. Everything below is live and interactive — the jersey players blink and breathe, runs roll with a slot animation, and every ball drops into the over track in real time.

01

Layout & hierarchy

structure
📐

Top-down scanning order

Eyes move score → teams → over → players. Keep that vertical stack fixed; never bury the big score under nav chrome.

Lead with runs/wickets in a huge display font
Equal-size text everywhere
🎯

One focal point per screen

The current score is the hero. Everything else is supporting cast. Use clamp() so it scales on mobile.

📱

Thumb-zone first

Live-match surfaces are watched on phones. Pin the score bar sticky at the top while the feed scrolls beneath it.

02

Jersey + player head

★ the signature look

The trick that makes it read as “a real player in a jersey”: the head is a separate layer that pokes out above the shirt, with a visible neck tucked into the collar, a team cap pushed down over the eyes, and the jersey drawn as a clip-path silhouette with the number printed on the chest. The head breathes and the eyes blink, so the player feels alive — not a flat sticker.

Why it works: layering. z-index order is jersey(1) → neck(2) → head(3) → cap(4). Because the neck overlaps the collar and the cap overlaps the forehead, the head reads as inserted into the shirt rather than pasted on top.

jersey.css — the layering recipe
/* torso as a T-shirt silhouette */
.jersey {
  clip-path: polygon(30% 6%, 40% 0, 60% 0, 70% 6%, 88% 14%, 100% 30%,
                     84% 42%, 82% 100%, 18% 100%, 16% 42%, 0 30%, 12% 14%);
  background: linear-gradient(160deg, #1b64ff, #0a2d99);
}

/* head pokes ABOVE the shirt top edge */
.head { top: -6px; z-index: 3; }        /* above jersey */
.neck { position:absolute; bottom:0; z-index:0; }  /* behind face, into collar */
.face { border-radius: 50% 50% 46% 46%; }     /* egg shape = human */
.cap  { top: -6px; z-index: 4; }        /* over the forehead/eyes */

/* make it feel alive */
.head { animation: breathe 4s ease-in-out infinite; }
.eyes i { animation: blink 4.5s infinite; }
03

Rolling run / ball updates

motion
🎰

Slot-machine digits

Render each digit as a vertical column 0–9 and translate the column with a CSS transition. Changing a value never re-mounts the DOM — it just slides.

⚡

Flash the pill, not the page

When a run lands, pulse the specific pill that changed (background flash) — a full-page animation is nauseating.

🧮

Recompute derived stats

Run-rate, required-rate, balls-remaining should all fall out of runs / overs in one render pass from the raw feed object.

roll.js
// digits: 0..9 stacked vertically; translateX pans to the target digit
function Roll(el) {
  el.innerHTML = '<div class="col">' +
    Array.from({length:10}, (_,i)=>`<span>${i}</span>`).join('') +
    '</div>';
  const col = el.firstChild;
  return d => col.style.transform = `translateY(${-d}em)`;
}

// on new ball: update runs/wickets, then flash only the changed pill
const setScore = Roll(document.querySelector('#runs'));
function applyBall(ball) {
  runs += ball.runs;
  setScore(runs);                       // rolls, no re-mount
  flashPill(document.querySelector('#pillRuns'));
}
04

Visualising overs

data-viz
⚪

The over track

One row of six circles = one over. Colour-code by outcome: green = runs, blue = four, gold = six, red = wicket, yellow = wide/no-ball. Label the running ball count.

📊

Manhattan bars

For long-form, render per-over total as a bar chart with wickets as red pips above the bar. Sparkline of run-rate over time adds instant context.

🔵

Wagon wheel

A cricket pitch centre with shots radiating out by angle + distance. Driving it from the balls array is a killer differentiator — few apps nail it.

overs.js
// map ball type -> css class, then push a dot into the current over row
const ballClass = b =>
  b.wicket ? 'w' : b.extra === 'wd' ? 'wd' :
  b.runs === 6 ? 'r6' : b.runs === 4 ? 'r4' :
  `r${b.runs}`;

const el = document.createElement('div');
el.className = `ball-dot ${ballClass(ball)}`;    // .r6 & .r4 & .w ...
el.textContent = ballLabel(ball);               // 0 1 4 6 W wd
currentOverEl.appendChild(el);                   // pop-in animation fires
if (ball.legal) overBalls++;
if (overBalls === 6) newOver();                 // 6 legal balls -> next over
05

Traps to avoid

gotchas
💾

Re-rendering the whole card

Never rebuild the scoreboard DOM on every ball — you lose the rolling animation and the player cards flicker. Patch in place.

⏱️

Trusting Date.now() for overs

Overs come from the feed as X.Y balls. Don't derive them from timestamps; the feed is the source of truth.

🌈

More than 5 accent colours

Pick one primary + one hot accent. Ball-outcome colours are a data palette — keep them separate from your brand palette.

🖼️

Low-res head cutouts

If you use real player photos, they must be transparent PNGs sized for a 2x display — a 40px photo scaled to 120px looks terrible.

06

Map CREX feed → UI

data
feed → scoreboard
// GET /api?matchId=... returns the live match object. Map minimal fields:
const { score, team1, team2, currentBatters, currentBowler, liveBalls } = feed;

scoreboard = {
  battingTeam : score.battingTeam,              // "India"
  runs        : score.runs,                     // 182
  wickets     : score.wickets,                  // 4
  overs       : score.overs,                    // "17.3"  -> display as-is
  runRate     : (score.runs / toOvers(score.overs)).toFixed(2),
  striker     : currentBatters.striker,         // renders on the ON-STRIKE card
  nonStriker  : currentBatters.nonStriker,
  bowler      : currentBowler,
  thisOver    : liveBalls.filter(b => b.over === score.currentOver),
};

// helper: "17.3" -> 17.5 overs (3 balls = half an over)
const toOvers = o => {
  const [ov, balls] = String(o).split('.').map(Number);
  return ov + (balls || 0) / 6;
};
